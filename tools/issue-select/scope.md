## Where candidates come from

Only issues in the course's Path Review repository are candidates:

- Repo: codepath/pathreview-ai301-fa26-s1 <!-- paste your section's repo from the Unit 1 Check-In page -->

Do not search, fetch, or grade issues from any other repository, however
promising. The wider GitHub comes later in the course; for now the field
is Path Review.

**Path Review house rule.** Path Review is a classroom, and your
classmates are not strangers. Ignore the usual claim signals here: other
students' claim comments (and there may be several on one issue) do not
block an issue, and finding some on the issue you want is normal. Claim
anyway: course credit attaches to the pull request you open, not to
whether it merges, so a shared issue costs nobody anything. Everything
else in the rubric applies as written.

Python is the language I have actually written and debugged, and I am
comfortable with Markdown docs and SQL. I have not worked in a compiled
language or a JavaScript front-end, so an issue that lives mainly in Java,
C++, or a React codebase is a poor fit for me right now.

What I want out of this one is practice reading code I did not write:
tracing an existing system well enough to find where a bug actually lives,
then reproducing it and covering it with a test. So I prefer bug reports
that come with reproduction steps or a stack trace over open-ended feature
requests.

I also want to finish. Among accepted candidates, rank the smallest,
best-scoped change highest, and prefer repos where a maintainer answers
issues, since I want real review feedback on the pull request rather than
silence.
